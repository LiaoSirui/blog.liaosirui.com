## 层次架构

常见的层次结构架构包括但不限于：

- 三层架构（Three-Tier Architecture）：由表现层（Presentation Layer）、业务逻辑层（Business Logic Layer，也称领域层或应用层）和数据访问层（Data Access Layer）组成。
- 多层架构（Multi-Tier Architecture）：在三层架构基础上进一步细化，可能包括额外的层，如基础设施层、服务层、消息层、安全层等。
- 微服务架构中的层次：虽然微服务架构强调服务的独立性，但单个微服务内部也可能按照层次结构组织，如 API 网关、业务服务、数据访问服务等。

## C/S

- 两层 C/S：胖客户机 = 界面 + 业务逻辑；服务器（数据库服务器） = 数据管理。
- 三层 C/S 把业务逻辑从客户机中分离出来，放到应用服务器上，客户机只负责用户交互，因此变成瘦客户机。

## RIA

RIA（Rich Internet Application，富互联网应用）

B/S 架构的增强版，结合了 B/S 和 C/S 的优点。传统 B/S 应用中，用户每次操作都要提交请求，服务器返回整个页面，客户端几乎不做处理，体验较差。

RIA 把一部分界面逻辑和数据处理放到客户端执行：

- 客户端可以在本地完成界面渲染、数据校验、局部计算；
- 与服务器通过异步通信交换数据，只刷新页面的局部内容；
- 用户操作不必等待整页刷新。

RIA = B/S 的部署便利 + C/S 的丰富交互，核心技术是异步通信和局部刷新（如 Ajax），属于层次架构风格中 B/S 方向的演进形式。

## MVC/MVP/MVVM

### Model-View-Controller

用户操作 View → Controller 处理请求 → 调用 Model 更新数据 → Model 通知 View → View 从 Model 读取数据并刷新

### Model-View-Presenter

MVP 是 MVC 的改进，用 Presenter 取代 Controller。

用户操作 View → View 转交给 Presenter → Presenter 调用 Model → Model 返回结果给 Presenter → Presenter 调用 View 接口更新界面

### Model-View-ViewModel

MVVM 在 MVP 基础上引入数据绑定。

View ⇄（双向数据绑定）⇄ ViewModel ⇄ Model
