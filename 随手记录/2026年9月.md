- 查看进程内核栈

```
ls /proc/3312258/task/ | wc -l

# 查看每个线程的内核栈
for tid in $(ls /proc/3312258/task/); do
    echo "=== Thread $tid ==="
    cat /proc/3312258/task/$tid/stack 2>/dev/null
    echo ""
done | grep -B1 -E "shrink|reclaim|try_to_free|mem_cgroup|writeback|page_fault|oom"
```

- 内存调试 thrashing

```bash
#!/bin/bash
CGROUP="/sys/fs/cgroup/kubepods.slice/kubepods-pod87d34b03_db92_4bb3_a7f3_2830aeed75ae.slice"

echo "=== 1. 内存使用 vs 限制 ==="
echo "current: $(cat $CGROUP/memory.current)"
echo "max:     $(cat $CGROUP/memory.max)"

echo ""
echo "=== 2. 压力指标 ==="
cat $CGROUP/memory.pressure

echo ""
echo "=== 3. 事件计数 ==="
cat $CGROUP/memory.events

echo ""
echo "=== 4. 回收统计（第一次）==="
grep -E "pgscan|pgsteal|pgfault|pgmajfault|workingset_refault" $CGROUP/memory.stat

sleep 5

echo ""
echo "=== 5. 回收统计（5秒后）==="
grep -E "pgscan|pgsteal|pgfault|pgmajfault|workingset_refault" $CGROUP/memory.stat

echo ""
echo "=== 6. 进程内核栈 ==="
cat /proc/3312258/stack 2>/dev/null || echo "进程可能已退出"
```

- 内存监控

cAdvisor 的取值（cgroup v2）：

```bash
# 和 OOM 判定同源
# 含大量可回收缓存 → 平时看着总是贴着 limit（内核本来就倾向于把内存用满做缓存）
container_memory_usage_bytes        = memory.current
container_memory_cache              = memory.stat: file
container_memory_rss                = memory.stat: anon

# 和 kubelet 驱逐一致
# 和 OOM 判定不是一个量 → 监控一片祥和，容器已被 OOMKilled
container_memory_working_set_bytes  = memory.current − inactive_file
```

关系式

```bash
usage ≈ anon(rss) + file(cache) + slab + sock + kernel_stack + percpu + ...
                     └── 注意：file 包含 tmpfs/shmem

working_set = usage − inactive_file
```

定性

```bash
# A. 总量
container_memory_usage_bytes{pod="..."}

# B. 缓存类（file + shmem）
container_memory_cache{pod="..."}

# C. 进程匿名内存
container_memory_rss{pod="..."}

# D. 驱逐 / top 视角
container_memory_working_set_bytes{pod="..."}

```

- 离线混部（全称在离线混部）是指将在线服务与离线任务部署在同一套物理机或集群资源上，通过资源隔离和动态调度技术，在保证在线业务稳定的前提下提高整体资源利用率。
  - 在线服务：如电商交易、网页浏览等。它们对响应时间（时延）极度敏感，但流量有明显的潮汐特征（白天高、夜间低），平时平均资源利用率不高。
  - 离线任务：如大数据计算、AI 模型训练、离线报表分析等。它们不直接面向用户，对时延不敏感，但会消耗大量计算资源。
  - 混合部署：让离线任务 “借用” 在线服务低峰期空闲的资源，或者通过超卖（Overcommit）压榨剩余算力
